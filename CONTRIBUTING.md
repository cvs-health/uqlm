## How to Contribute

For quick questions or community discussion, join our [Discord](https://discord.gg/RjcrAPw43H). For bug reports and feature requests, please use GitHub issues as described below.

### Reporting Bugs

If you find a bug, please report it by opening an issue on GitHub. Include as much detail as possible:
- Steps to reproduce the bug.
- Expected and actual behavior.
- Screenshots if applicable.
- Any other information that might help us understand the problem.

### Suggesting Enhancements

We welcome suggestions for new features or improvements. To suggest an enhancement, please open an issue on GitHub and include:
- A clear description of the suggested enhancement.
- Why you believe this enhancement would be useful.
- Any relevant examples or mockups.

### Pull Requests

1. Fork the repository.
2. Create a new branch (`git checkout -b feature/your-feature-name`).
3. Make your changes.
4. Commit your changes (`git commit -m 'Add some feature'`).
5. Push to the branch (`git push origin feature/your-feature-name`).
6. Open a pull request.

Please ensure your pull request adheres to the following guidelines:
- Follow the project's code style.
- Include tests for any new features or bug fixes.

## Development Setup

1. Clone the repository: `git clone https://github.com/cvs-health/uqlm.git`
2. Navigate to the project directory: `cd uqlm`
3. Create and activate a virtual environment (using `venv` or `conda`)
4. Install uv (if you don't already have it): `pip install uv` or `curl -LsSf https://astral.sh/uv/install.sh | sh`
5. Install uqlm with dev dependencies: `uv sync --group dev`
6. Install our pre-commit hooks to ensure code style compliance: `pre-commit install`
7. Run tests to ensure everything is working: `pre-commit run --all-files`

You're ready to develop!

## Style Guides

### Code Style

- We use [Ruff](https://github.com/astral-sh/ruff) to lint and format our files.
- Our pre-commit hook will run Ruff linting and formatting when you commit.
- You can manually run Ruff at any time (see [Ruff usage](https://github.com/astral-sh/ruff#usage)).

Please ensure your code is properly formatted and linted before committing.

## AI Policy

"AI" here refers to generative AI tools, such as large language models (LLMs), that can generate, edit, or review code, or generate human-like communication.

uqlm is research software published in JMLR. The uncertainty quantification methods implemented here are mathematically nuanced, and incorrect code can silently produce results that look plausible but are scientifically invalid. Given this, we hold contributions to a high bar of scientific correctness, and AI generated code that has not been rigorously verified against the underlying methodology will not be accepted.

### Responsibility

You are responsible for any code you submit to uqlm's repositories, regardless of whether it was written manually or generated by AI. You must understand and be able to explain the code you submit, as well as the existing related code it touches. It is not acceptable to submit a change that you cannot understand and explain yourself. Do not use AI to automatically generate commit messages, pull request descriptions, or issue descriptions.

### Disclosure

You must disclose whether AI was used to help develop your pull request. If so, note which tool(s) were used, how they were used, and what parts of the change are AI generated. Pull requests that omit this disclosure will be rejected.

### Code Quality

Code must meet uqlm's standards regardless of how it was produced. We will reject pull requests that are "AI slop": code that is fully or mostly AI generated and does not meet our standards, or that the author cannot explain and has not tested.

### Copyright

uqlm is released under the Apache 2.0 license, and contributors license their code under the same terms when it is merged into uqlm. You must own the copyright of any code you submit, or include a compatible open source license for it. Code generated by AI can infringe on copyright, and it is your responsibility to ensure it does not. We reserve the right to reject any pull request, AI generated or not, where copyright is in question.

### Communication

When interacting with maintainers and other contributors (issues, pull requests, discussions), do not use AI to speak for you, aside from translation or grammar editing. Human to human communication is important to keep this community healthy.

### AI Agents

An AI agent that writes code and submits a pull request autonomously, without a human reviewing the change and taking responsibility for it, is not permitted. A human must check any generated code and submit the pull request per the Responsibility section above.

This policy is adapted from [NumPy's AI policy](https://numpy.org/devdocs/dev/ai_policy.html).
